# Per-completion publication/admission bridge

Isolated development only. No production code, service, gain, collection, retention or routing changes. The FR24 stock-only experiment continues until 1 November at 20:00 Europe/Berlin.

`CompletionPool` observes completed worker futures before the original ordered grouping path. It owns copies of raw events: merging each future independently is unsafe because the seam deduplication is non-transitive. The unchanged normal `pop` still assembles whole seconds for statistics and collection. `Bridge` independently admits completed events using the existing `rescue.shadow.evaluate`, an indexed causal stock history, rolling energy alignment, stock-progress checks and shared five-RF-second deduplication. CRC/address/conflict/120us checks remain. Broad CRC stays quarantined. Pending queues and energy anchors are bounded, with explicit failure/drop counters. The caller must call `begin_epoch` on a new original RF session; a late old future cannot reset the current epoch.

`publish_to` is an optional sink for the existing experimental `AsyncFanIn`: individual guarded events enter their method queues with original sample timestamps. It opens no sockets and is not attached to a feeder. The target benchmark measures bridge admission before this additional transport stage; it does not claim TCP-delivery latency.

`capture.py` acquires at most eight seconds from the idle optional mirror, with stock/relay/reference/position context, 35-second warmup and eight-second reference tail. It refuses an active consumer, keeps its heartbeat until closure and never opens the SDR or flushes the recorder. Capture origin `(0,0)` is unused; real position context stays private. All RF is reserved evaluation-only before replay.

`benchmark.py` replays real copied production algorithms/models on the Pi, pacing eight contiguous RF seconds into the original 100ms assembler. CPU topology is intentionally restricted to one core / 35% quota; two roles still share the same native FIR/ring calculations. Noise prewarm is separate. Both completed-event and normal-grouped outputs are preserved, with exact grouping checks. Baseline is unchanged full-window admission on the same RF. Actual producer/relay references are checked separately. The 22 Stream1090 extras in this capture originate outside the pool and are explicitly excluded from the pool baseline.

Run tests with project Python and `PYTHONPATH=src`. Run target benchmarks only in an owned copied tmpfs stage with nice19/core3/CPUQuota35%/MemoryMax1G/finite runtime and `protected.py`. Never run these against live production output paths. Keep the captured data/model/source snapshots private. The raw timing origin is estimated from final-batch readiness: USB/input latency is not measured. No training, model changes or RF parameter fitting occurred.

Engineering history is preserved privately: attempt1 hit an overly short harness deadline; attempt2 used separated RF seconds and exposed a rolling-anchor retention defect; attempt3 fixed pending-window anchor retention and used contiguous pacing; attempt4 repeats after adding explicit old-epoch rejection (same decoder/thresholds). These are repeated engineering tests on the same eight RF seconds, not independent prospective validations. A later unused publication adapter has a separate synthetic unit test; it does not alter benchmarked admission behavior. No parameters were tuned on test RF.

The CPU cap prevents this duplicated full-DSP observer from demonstrating production sub250ms latency. Keep the working pipeline unchanged. Consult the dated report for exact results and limits.

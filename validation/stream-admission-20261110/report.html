Incremental native Stream1090: admission and test-relay validation

10 November 2026, Europe/Berlin. Isolated historical RF replay; nothing deployed. Hardware: Raspberry Pi 5 Model B Rev 1.0.

The 20 ms decoder now has a test admission bridge and one shared Rust final transmission history. Energy runs independently in 50 ms blocks. Original stock arrivals are replayed causally; final output reaches an anonymous RAM-only socket sink, never a feeder. The original one-second logical reset remains intact.

Controls and live state

Twelve synthetic admission/dedup/socket controls passed on Mac and Pi. The previous incremental study's boundary, split, deadline, overflow, noise, exact-packet and sanitizer checks remain applicable: the native incremental decoder was unchanged. Original-first stock identity/conflict guards, CRC and alignment requirements were retained. Late stock always passes and its duplicate race is counted. Protected PIDs/configuration/methods/gain/cap and primary sample-loss counters unchanged during the completed target run: True. No receiver, feeder, relay or collector restart, routing change, archive deletion or flush occurred. The RF cap remains 5,000,000,000 bytes.

Separate pre-existing live event: the native rollback guard restored the executable at 16:37:15 UTC, before this admission experiment, after a primary sample-loss counter increase. The isolated reference is the previously validated native batch library. The guard trigger does not establish causation. This task leaves the executable fallback unchanged. FR24 and collection remain connected.

The initial complete Pi prototype lost 13 of the 48 transmissions emitted by its also-overloaded batch condition; 31 of the 79 deferred-reference extras were already rejected by that initial batch condition. Cached watermark scanning alone then retained 74/79. These failed gates are preserved with their exact source copies. Candidate-specific indexes reduced incremental CPU from 0.6191 to 0.3704 CPU seconds per RF second (about 40%), retaining 79/79. No age threshold, CRC guard, decoder rule or clock tolerance was relaxed. A separate Mac audit required the narrowed and original full-index admission functions to return identical outputs, alignment audits and counters for every slice.

Two setup attempts stopped before RF replay: macOS transfer metadata was treated as a source filename; then preflight found that the expected live native library had already been removed by rollback. Both failures are preserved privately. The completed target runs verify the pinned native baseline and actual unchanged executable configuration explicitly.

Next gate

Keep this experimental. First remove remaining Python admission/copy overhead and reuse the existing production energy frontend instead of duplicating it. The current result is not a sub-250 ms Pi deployment candidate under this quota. Before a production admission/publication change, validate on longer untouched RF with adequate distant opportunities, real tap-arrival timestamps and all-method completion journals. Review the rollback's sample-loss event separately before considering another native activation.
